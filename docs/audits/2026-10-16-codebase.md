# Independent codebase audit — 16 October 2026

The current working tree has one high-priority functional defect and three narrower correctness defects despite passing the coordinator's deterministic test gates. Most built-in Rust STAC providers construct the wrong search path. A boundary case also lets the explorer stop with an omitted observation while reporting a complete scan.

## Scope and provenance

This agent independently inspected TypeScript, Python and Rust catalogue/query/normalization/availability code; explorer orchestration and preview handling; manifests and lockfiles; shared conformance fixtures; current documentation; and CI/package-checking configuration. Production source was read-only. Only this report and the uniquely named `tools/audit/results/2026-10-16-codebase*` evidence files were written by this agent.

Base commit: `139ab2963d28d5317f3608a6d635ef07465f2b68` (13 October 2026). The working tree was already extensively modified, including SDKs, explorer, registry, documentation and CI. Findings describe that current tree; they are **not** a claim that the unmodified commit was fully tested. `git show HEAD:<path>` confirms the underlying faulty logic for findings C1–C4 and the C5 lock version already exists in HEAD. The new INPE Rust constructor extends C1 to one additional provider.

Severity uses P1 = major supported functionality broken; P2 = incorrect/misleading results under a supported but narrower input; P3 = limited boundary defect or maintenance issue. Confidence is separate from severity.

## Findings

### C1 — P1: Most built-in Rust STAC providers discard their last base-path segment

**Confidence: confirmed, real SDK against a local HTTP server.**

Evidence: `crates/satellites-images/src/lib.rs:809` calls `self.endpoint.join("search")`. The base constants at lines 26–28 and constructors at lines 679 and 702 omit a trailing slash. URL joining treats the last segment as a filename and replaces it.

| Provider | Constructed request path | Intended request path |
| --- | --- | --- |
| Planetary Computer | `/api/stac/search` | `/api/stac/v1/search` |
| Copernicus Data Space | `/search` | `/v1/search` |
| USGS LandsatLook | `/search` | `/stac-server/search` |
| INPE CBERS | `/bdc/stac/search` | `/bdc/stac/v1/search` |
| NASA CMR, ASF example | `/stac/search` | `/stac/ASF/search` |
| Earth Search, control | `/v1/search` | `/v1/search` |

The independent offline probe exercises `StacProvider::new` and `search_pages`, recording the actual received HTTP path for three representative nested bases and the trailing-slash control. Provider-specific impact is established by inspecting the exact built-in base strings; this agent did not run live Rust provider searches. The source-validation agent separately owns live endpoint evidence.

```sh
python3 tools/audit/results/2026-10-16-codebase-rust-path.py
```

The probe reuses existing debug rlibs and compiles only its small driver. Its default compiler is Rust 1.88.0; set `AUDIT_RUST_TOOLCHAIN` to the compiler used for those rlibs when rerunning after another build. Captured output: [Rust path log](../../tools/audit/results/2026-10-16-codebase-rust-path.log).

Observed output includes `/api/stac/v1 → /api/stac/search`, `/bdc/stac/v1 → /bdc/stac/search` and `/stac/ASF → /stac/search`; the `/v1/` control correctly requests `/v1/search`.

**Remediation:** normalize the STAC endpoint to a directory before joining, consistently for custom and built-in providers. Add request-path assertions for nested bases with and without trailing slashes and for each built-in constructor. Normalization-only INPE tests currently check its ID and recorded item, not the requested URL (`crates/satellites-images/tests/inpe.rs:8`).

### C2 — P2: Explorer can stop at its page cap and falsely report complete coverage

**Confidence: confirmed with the exact current orchestration function and real SDK generators; no browser run claimed for this specific probe.**

Evidence: `apps/explorer/src/main.ts:1305` marks a session ended after 50 aggregate pages. At lines 1324–1325 it clears status if `summary.complete` is true. `packages/typescript/src/availability.ts:95` uses the most recently yielded page's `hasNext`. A STAC split-box provider can yield `hasNext=false` at the end of its first box while another box remains to search.

The reproduction uses the ordinary provider order from `main.ts:1416` and a valid centre/radius query at longitude 180:

1. Planetary Computer completes 1 east-box page and 4 west-box pages.
2. Earth Search completes 45 east-box pages; the last has no pagination next link.
3. The explorer now has 50 aggregate pages and stops before Earth's west box.
4. Both providers' last pages have `hasNext=false`, so the summary says `complete=true`; status is empty and `truncatedProviders=[]`.
5. Consuming one more generator page reveals the valid scene `omitted-west-scene`.

```sh
node tools/audit/results/2026-10-16-codebase-cap.mjs
```

This probe extracts `scanNextBatch` verbatim from `main.ts`, strips TypeScript types with Node's API, and replaces only UI rendering/state controls with stubs. It ran on Node 25.5.0; Node 20 lacks the type-stripping API used by this audit artifact. [Captured output](../../tools/audit/results/2026-10-16-codebase-cap.log) records `pagesScanned:50`, `complete:true`, `stoppedByExplorer:true`, and the omitted scene.

**Remediation:** track iterator/provider/subquery exhaustion independently of a page's pagination link. Reaching an aggregate safety cap with unconsumed work must force partial status. Add an offline browser regression for a split-box scan stopping exactly at that boundary. The broad hypothesis about ordinary initial scans spanning multiple date chunks was not asserted: the current initial year uses one 12-month chunk.

### C3 — P2: A supported MultiPolygon can lose an entire requested region when another polygon crosses the antimeridian

**Confidence: executed in TypeScript and Python; matching Rust implementation inspected.**

Evidence: TypeScript `packages/typescript/src/index.ts:200`, Python `packages/python/src/satellites_images/catalog.py:239`, Rust `crates/satellites-images/src/lib.rs:275` compute one pair of seam bounds over every ring once any ring crosses the antimeridian.

A valid MultiPolygon consisting of a rectangle between 179°E and 179°W and a separate rectangle from longitude −1 to +1 produces only these boxes:

```json
[[-180,0,-1,12],[1,0,180,12]]
```

The requested interior point `[0,0.5]` lies in neither box. `resolveAreas`/`resolve_areas` removes the original `intersects` geometry whenever two boxes are generated, so no later exact filter restores that omitted region.

```sh
node tools/audit/results/2026-10-16-codebase-spatial.mjs
PYTHONPATH=packages/python/src python3 tools/audit/results/2026-10-16-codebase-spatial.py
```

[TypeScript output](../../tools/audit/results/2026-10-16-codebase-spatial-ts.log) and [Python output](../../tools/audit/results/2026-10-16-codebase-spatial-python.log) both record `boxesCoverRequestedPoint:false`. Rust was not separately executed for this geometry case.

**Remediation:** split each polygon component independently and union the resulting safe query regions, or use a conservative enclosing query with a documented exact spatial post-filter. Include mixed ordinary/dateline MultiPolygons in shared conformance fixtures.

### C4 — P3: Full-day STAC searches omit fractional timestamps in the final second

**Confidence: request construction and omitted-item behavior executed in TypeScript/Python; matching Rust construction inspected.**

Evidence: TypeScript `packages/typescript/src/index.ts:289`, Python `packages/python/src/satellites_images/catalog.py:483`, Rust `crates/satellites-images/src/lib.rs:797` end an inclusive daily interval at `T23:59:59Z`.

The spatial probe above also supplies a mocked provider that applies the transmitted timestamp interval to an existing item at `2025-01-01T23:59:59.500Z`. Both SDKs request `2025-01-01T00:00:00Z/2025-01-01T23:59:59Z`, receive zero items and report `complete=true`. That timestamp belongs to the requested day but is outside the transmitted interval. Rust's identical construction was inspected; this specific Rust boundary was not executed. JAXA uses the same second-level upper bound; its service precision was not independently established here.

**Remediation:** define full-day interval semantics and supported precision centrally, then query through the next day's boundary and filter exact UTC dates when needed, or use a provider-supported date interval representation. Test final-second fractions and adjacent-day exclusion across SDKs.

### C5 — P3: Locked rustls is covered by four current advisories; current configuration does not demonstrate their exploit paths

**Confidence: lock version and enabled features confirmed; applicability is source/configuration analysis, not an exploit test.**

`crates/satellites-images/Cargo.lock:740` locks `rustls 0.23.45`. The coordinator's `cargo audit --json --file crates/satellites-images/Cargo.lock` reports four advisories, all patched in `>=0.23.46`. Evidence: [scanner JSON](../../tools/audit/results/2026-10-16-cargo-audit.json). This agent verified the official advisory pages on 16 October 2026 and ran:

```sh
cargo tree --manifest-path crates/satellites-images/Cargo.toml --locked --offline -e features -i rustls
```

[Feature-tree output](../../tools/audit/results/2026-10-16-codebase-rustls-features.log) shows `ring`, `std`, and `tls12`; there is no `brotli` feature. Source search found ordinary `reqwest::Client::builder()` construction and no custom Rustls configuration.

| Advisory | Required condition and current applicability |
| --- | --- |
| [RUSTSEC-2026-0346](https://rustsec.org/advisories/RUSTSEC-2026-0346.html) | TLS secret exposure through custom session-store debug logging. No such implementation or logging was found; built-in cache debug output is excluded by the advisory. |
| [RUSTSEC-2026-0347](https://rustsec.org/advisories/RUSTSEC-2026-0347.html) | Enabled ECH plus application data buffered before a rejected ECH handshake. No ECH configuration or direct pre-handshake data writes were found. |
| [RUSTSEC-2026-0348](https://rustsec.org/advisories/RUSTSEC-2026-0348.html) | Brotli certificate decompression allocation issue. The required `brotli` feature is absent in the checked graph. |
| [RUSTSEC-2026-0349](https://rustsec.org/advisories/RUSTSEC-2026-0349.html) | Unauthenticated key-share prediction can remove post-quantum protection. The selected Ring provider offers classical X25519/P-256/P-384 only, so that additional post-quantum downgrade is not demonstrated here. A consumer unifying different features/providers would need reassessment. |

**Remediation:** update the transitive lock selection to a patched Rustls release and rerun Rust checks, minimum-runtime and package acceptance. This is a dependency hygiene recommendation; it is not evidence of four exploitable project vulnerabilities. No dependency changes were made.
