# Independent source audit and live latency measurements

Observed **16 October 2026** using anonymous metadata requests. The audit covers all
21 registry entries and independently repeats the 25-entry supplied-list review.
No credentials, accounts, imagery downloads, orders or uploads were used. HTTP 200
for documentation is recorded separately from a successful observation query.

## Results that affect integration

1. **INPE works through the TypeScript adapter and direct browser POST.** A bounded
   Brazil circle returned one observation in each of three trials. A separate
   polygon query returned two then one observations, `matched: 3`, with the final
   page `hasNext: false`. Missing mission, GSD and cloud cover remain null. The
   returned date is midnight; it does not establish acquisition-hour precision.
   The wider source-review query outside Brazil returned zero, rather than a
   fabricated coverage result. The sampled thumbnail HEAD returned 200 without
   an allow-origin header; its use as a map/canvas image remains unverified.
2. **NISAR and ALOS-2 return actual ASF metadata and work in Chromium.** Both
   capped two-item responses correctly retained `hasNext: true`, `matched: null`
   and `authentication-required` scene access. NISAR preserves provisional product
   identifiers in native properties. These are radar products; the tests do not
   establish an optical preview or download entitlement. ASF Sentinel-1's narrower
   historical test window returned valid empty metadata, not a positive scene test.
3. **USGS LandsatLook and OpenAerialMap work from Node but fail direct Chromium
   fetches from an arbitrary localhost origin.** USGS returned no allow-origin
   header; OAM advertised `https://map.openaerialmap.org`. Their optional browser
   integrations would need a dedicated origin-restricted proxy; the repository's
   ESA-only proxy does not provide that route. This reproduces their documented
   restriction; it is not a new backend outage.
4. **Wyvern, Capella and Umbra remain candidates.** All three static roots work in
   Chromium and each representative static traversal reaches a dated scene. This
   does not verify Item Search, complete indexing, deduplication or SDK adapters.
   Wyvern's sampled collection says `CC-BY-4.0`, while the scene's native
   `properties.license` says `proprietary`; Capella's sampled collection also says
   `proprietary`. A future adapter needs explicit programme-licence provenance
   rather than silently replacing native metadata. The Umbra sample lacks an
   advertised PNG/JPEG browser preview.
5. **A Rust URL-construction defect has independent live corroboration.** The
   incorrect INPE path `/bdc/stac/search` returned HTTP 302 to the correct
   `/bdc/stac/v1/search`; `redirect: "error"` failed. Posting directly to the
   correct path returned 200 GeoJSON. TypeScript results do not verify Rust
   presets. The code audit owns the root cause, scope and remediation; this
   report records the observed pre-fix service behaviour.

## Latency baseline

Metric: wall-clock time to consume the bounded TypeScript SDK query, including
network, body reads, JSON parsing and normalisation. All samples are sequential;
no load or throughput test was performed. Environment: Node **v25.5.0**, macOS
Darwin **25.6.0**, arm64, **Apple M1 Max**. The deterministic suite was running
concurrently during part of the source audit; these are operational observations,
not isolated CPU measurements. No performance target or before/after change was
defined. Exact queries, request headers, page counts and sample times are in JSON.

| Provider/workload | Samples | Median | Range | Result per sample |
| --- | ---: | ---: | ---: | --- |
| Earth Search, Lombok May 2025, cap 2 | 3 | 781 ms | 760–808 ms | 2 scenes; partial, matched 20 |
| Planetary Computer, same AOI/date/cap | 3 | 152 ms | 125–209 ms | 2 scenes; partial, total unknown |
| Copernicus, same AOI/date/cap | 3 | 219 ms | 121–265 ms | 2 scenes; partial, total unknown |
| INPE, Brazil 13 October 2026, cap 1 | 3 | 288 ms | 262–727 ms | 1 scene; complete for this query |
| ASF NISAR, Lombok September–15 October 2026, cap 2 | 3 | 3,163 ms | 1,825–12,154 ms | 2 scenes; partial |

Single-trial diagnostics: ALOS-2 **4,344 ms**, USGS **694 ms**, JAXA G-Portal
**1,829 ms**, OpenAerialMap **368 ms**, ASF Sentinel-1 **3,659 ms** (zero items),
CMR/ASF **693 ms** (zero items). A deliberately bounded Maxar traversal took
**2,787 ms / 12 metadata documents**, returned zero scenes and retained
`hasNext: true`; this is an unfinished search, not evidence of no Maui imagery.
ESA took **4,386 ms / 7 metadata requests**, returned **2 planned opportunities**
with diagnostics status `ok`; these are plans, not acquired observations.

The SDK benchmark made **22 query trials and 33 metadata requests**, with no
request-level failures. CMR and ASF Sentinel-1 demonstrate valid empty queries,
not positive coverage. The 12-document Maxar cap is intentionally far below the
adapter default and is unsuitable for comparison with one-request STAC queries.

ASF NISAR is the largest measured latency and variance contributor in this set.
The first query took 12.154 s and later identical queries 3.163 s and 1.825 s.
Connection reuse and service/cache state may explain part of the difference; this
audit cannot isolate them from network and provider execution time. First samples
have unprimed process/provider caches, but OS DNS caches and remote caches are
uncontrolled. Different provider collections, responses and AOIs prevent treating
these numbers as an equal-workload provider ranking. Three samples cannot
establish a p95 or production SLO.

## Reproduce

```sh
npm run build -w @powerpuff-kitty/satellites-images
node tools/smoke/source-review.mjs --out /tmp/source-audit.json
node tools/smoke/source-benchmark.mjs --out /tmp/source-benchmark.json
node --check tools/smoke/source-benchmark.mjs
```

The benchmark requires the repository's installed Playwright Chromium and uses an
ephemeral local HTTP server to establish a real arbitrary browser origin. It never
loads map imagery. Browser CORS preflights are additional transport requests and
are not included in the 33 SDK request count. Sources and their catalogues can
change; query dates and AOIs are fixed in the script to make workload changes clear.

Priorities: resolve the Rust preset defect using the independent code audit;
retain proxy gating for restricted browser APIs; preserve provisional status,
unknown resolution, licence provenance and partial-result indicators; establish
longer longitudinal measurements before changing provider timeouts or claiming a
latency improvement. This audit made no production implementation changes.
