# Project, source and performance audit — 16 October 2026

Two independent agents audited the codebase and live sources. The coordinator ran
the deterministic gates, minimum-runtime checks, advisory scanners and repeated
CPU benchmarks, and independently reran the geometry/time and explorer-cap
reproductions. The checked working tree is based on
`139ab2963d28d5317f3608a6d635ef07465f2b68` and was already extensively modified.
These results describe that tree, not a clean release or hosted CI run.

**Result:** the existing test gates pass, with four reproduced correctness defects
and one dependency-maintenance finding. No production fixes were applied. New
files are audit reports, evidence and reproducible measurement scripts; no
credentials, releases, imagery uploads or workflow changes were involved.

## Findings to address

| Priority | Finding | Practical effect | Next change |
| --- | --- | --- | --- |
| P1 | Rust STAC URL construction replaces the final base-path segment | Five built-in presets request the wrong search endpoint; the new INPE preset inherits this existing defect | Normalize base URLs as directories and assert real request paths for every preset |
| P2 | Explorer global 50-page cap can leave work unconsumed while showing complete | A split-box search omits a valid scene and clears the partial-result warning | Track iterator/subquery exhaustion independently of page-level `hasNext`; cap must force partial while work remains |
| P2 | Mixed dateline/ordinary MultiPolygon loses requested territory | The reproduced query excludes `[0,0.5]` inside its Greenwich component | Split polygon components separately; add shared spatial contract cases |
| P3 | Full-day STAC query ends at exactly `23:59:59Z` | A scene at `23:59:59.500Z` is omitted, with a complete summary | Define inclusive-day semantics, including fractional timestamps and adjacent-day exclusion |
| P3 | Locked Rustls 0.23.45 is covered by four current advisories | Scanner fails; no advisory exploit path was demonstrated with the current features/configuration | Select a patched transitive version and rerun Rust/minimum/package checks |

The [independent code audit](2026-10-16-codebase.md) contains exact source lines,
severity definitions, runnable reproductions and primary advisory references. The
underlying faulty logic already exists in HEAD; the INPE addition broadens the
Rust URL issue to another preset. Geometry/time failures were executed in TS and
Python, with matching Rust code inspected; the Rust URL failure used the actual
Rust SDK against a local HTTP server. The explorer-cap case used the exact current
orchestration function and real SDK generators, with UI callbacks stubbed.

This exposes a test gap: normalization and installation success do not verify
the URL a built-in provider actually requests. The existing fixture suites did
not exercise these particular query-boundary and orchestration cases.

## CPU benchmark baseline

Three final sequential trials per language, after browser and test/compiler work
finished. Each existing benchmark warms up 10% of its iterations; Rust uses release
optimization and `black_box`. Environment: **Apple M1 Max**, 10 logical CPUs,
32 GiB RAM, macOS **26.7**, arm64; **Node 25.5.0**, **Python 3.14.7**, **Rust 1.94.1**.
No project performance SLO exists: these are measurements, not pass/fail targets.

| Operation | TypeScript median ops/s | Python median ops/s | Rust median ops/s |
| --- | ---: | ---: | ---: |
| Polygon bounds | 5,834,320 | 207,933 | 8,296,575 |
| Antimeridian polygon bounds | 4,120,596 | 197,418 | 8,186,460 |
| Bounding-box coverage calculation | 19,352,968 | 571,897 | 41,976,400 |
| Availability summary: 50 pages × 100 scenes | 589 | 165 | 298 |
| JAXA feature normalization | 692,050 | 154,360 | 345,219 |
| ASF feature normalization | 931,210 | 171,433 | 544,139 |

A **5,000-scene availability summary** took a median **1.70 ms TS**, **6.06 ms
Python**, **3.36 ms Rust**. Throughput ranges were 478–597, 156–176 and 280–304
summaries/s respectively. Short geometry timings were noisier: TS antimeridian
throughput ranged from 2.20M to 4.14M ops/s. Three runs do not establish tail
latency. Implementations and allocation patterns differ; this is not a general
language ranking. Synthetic inputs, JIT state, CPU scaling and background system
activity limit generalization.

[Raw trials, rounded timings and environment](../../tools/bench/results/2026-10-16-audit.json)
are captured by:

```sh
npm run check
node tools/bench/audit.mjs --out /tmp/sdk-benchmark.json
```

The historical 2026-10-13 artifact used Node 24.19.0 and a different working tree.
No controlled regression/improvement claim is made from that comparison. No
optimization was applied, so there is no before/after improvement result.

## Live-source results

The [independent source audit](2026-10-16-sources.md) covers **all 21 registry
entries** and repeats **all 25 supplied-list entries**. It records **53 probes**:
52 HTTP 200 responses and CORONA's HTTP 403. Some probes establish documentation
or capability reachability only; they do not establish a searchable scene source.

There were **22 bounded SDK query trials / 33 metadata requests**, without
request-level failures. Chromium fetched nine of eleven tested routes; USGS and
OpenAerialMap were blocked by their origin policies, while their Node queries
succeeded. INPE's actual SDK pagination returned **2 + 1 observations**, matched 3,
and finished without `hasNext`. NISAR and ALOS-2 yielded radar metadata and retained
partial status at their caps. Wyvern, Capella and Umbra remain static-catalogue
candidates, not implemented search adapters. Wyvern's sampled item/collection
licence labels conflict, adding a provenance requirement to the earlier review.

| Bounded SDK query | Median of 3 trials | Observed range |
| --- | ---: | ---: |
| Earth Search | 781 ms | 760–808 ms |
| Planetary Computer | 152 ms | 125–209 ms |
| Copernicus | 219 ms | 121–265 ms |
| INPE CBERS | 288 ms | 262–727 ms |
| ASF NISAR | 3,163 ms | 1,825–12,154 ms |

Network measurements include provider execution, transport, body reads, JSON and
SDK processing. Inputs/collections differ, caches are uncontrolled, and part of
the source audit overlapped deterministic testing. They are operational samples,
not equal-workload provider rankings or p95 estimates. ASF/NISAR was the largest
measured latency and variance contributor; the audit did not isolate its cause.
The measured millisecond CPU summaries are much smaller than these chosen network
queries, suggesting I/O deserves investigation before CPU optimization for this
usage. That is a workload-specific inference, not a production profile.

## Recommended order

1. Repair Rust path construction and add real request-path coverage.
2. Repair completeness and mixed-component spatial bounds, then fractional-day
   intervals; preserve the new reproductions as shared contract/browser tests.
3. Select patched Rustls dependencies and rerun minimum-runtime/package gates.
4. Preserve CORS gating, partial indicators, licence provenance and unknown item
   metadata while adding sources. Keep network sampling longitudinal before
   changing timeouts, caching or source priorities.

The audit did not authenticate to providers, download raster imagery, validate
georeferencing/licences for every asset, perform load/penetration testing, or
publish anything. Passing test suites and reachable documentation are bounded
evidence; the reproduced defects and untested routes remain explicit above.
